# Critix: согласованные решения и границы первой реализации

React + TypeScript + Vite + Mantine + React Flow → FastAPI → service → analysis engine → SQLAlchemy 2.0 → PostgreSQL.
AI — отдельный модуль backend с HTTP-интерфейсом к LLM. Очередей и дополнительных сервисов нет.

## Данные и транзакции

Руководитель входит в единственный аккаунт. Исполнители не имеют учётных записей.
Проекты, исполнители, задачи, зависимости и версии изменений хранятся в отдельных таблицах.
Составные внешние ключи запрещают связи и назначения между проектами.
Редактирование сохраняет агрегат проекта целиком. Короткая разделяемая блокировка строки
защищает чтение согласованного снимка. Расчёт проходит без блокировки и открытой транзакции.
Перед записью сервер берёт эксклюзивную блокировку, повторно проверяет версию и атомарно
записывает снимок и анализ. Чужое сохранение во время расчёта также приводит к 409.
Устаревшая версия возвращает 409. What-if выполняет те же расчёты без записи.
Удаление задачи требует удалить её связи из передаваемого агрегата; UI делает это в черновике явно.

## Время и длительность

- Точность — одна минута; UI показывает рабочие часы. Длительность не означает трудоёмкость.
- Занятость 50% не удваивает длительность; она участвует только в выявлении перегрузки.
- Даты API содержат смещение UTC. Рабочие смены интерпретируются в IANA-поясе проекта.
- Смены внутри суток, с перерывами; ночная смена задаётся двумя дневными интервалами.
- Исключение заменяет расписание недели на конкретную дату. Пустой список означает нерабочий день.
- Индивидуальный календарь пересекается с календарём проекта. Без исполнителя используется календарь проекта.
- Праздники и отпуска задаются явно; встроенного производственного календаря по странам нет.
- Длительность начатой задачи — общая ожидаемая длительность от фактического начала.
- Фактические даты завершённых задач сохраняются; противоречия связям отмечаются риском.
- Автоматического пересчёта остатка по текущему времени пока нет: это план, а не учёт фактических трудозатрат.

## Движок

Топологическая сортировка DAG — O(V+E). Цикл отвергается до записи.
Каждый тип связи задаёт нижнюю границу начала или окончания последователя.
FS: finish(A) → start(B), SS: start(A) → start(B), FF: finish(A) → finish(B), SF: start(A) → finish(B).
Задержка с любым знаком отсчитывается либо в реальных минутах, либо по пересечённому календарю последователя.
Прямой проход вычисляет минимальное допустимое расписание; обратный проход — максимально позднее без изменения прогноза завершения.
В обратном проходе используется монотонный поиск: простое вычитание задержки некорректно на разных календарях.
Slack измеряется рабочими минутами конкретной задачи относительно прогнозного завершения, а не целевого дедлайна.
Фиксированные фактические даты не имеют вычисляемого slack. Критических ветвей может быть несколько.

Календарная сетка материализуется по минутам в ограниченном горизонте: от начала минус 370 дней до начала плюс 740 дней.
Предельный заявленный срок проекта — год; максимум 200 задач, 2000 связей и 100 исполнителей.
Это эксплуатационные ограничения первой реализации, а не сокращение типов зависимостей или календарей.
Сложность с учётом сетки W и числа разных календарей C: O(C·W + (V+E)·log²W),
память O(C·W+V+E); сканирование интервалов загрузки дополнительно пропорционально рабочим минутам задач.
Для крупных проектов потребуется интервальное представление календарей; текущая версия рассчитана на небольшие проекты.

## AI

Внешнему API передаются название проекта, названия задач и готовый анализ. Ключ хранится только на сервере.
Ответ — пояснение и гипотезы действий. Он не участвует в расчётах и не изменяет проект.
Без ключа или при ошибке провайдера планирование продолжает работать. Провайдер и модель задаются окружением.

POST /api/projects/{id}/chat принимает последние 10 сообщений и необязательный текущий
черновик; его анализ выполняет backend. История хранится в localStorage браузера.
Чат не применяет изменения. Анализ и чат используют общий строгий _SYSTEM; клиенту
разрешены только user/assistant, до 10 сообщений по 8000 символов. Без ключа, модели,
при пустом ответе или ошибке провайдера возвращается available=false. Шаблонного AI-ответа нет.

## Дополнения текущей версии

Assignee.role — необязательное поле должности/роли; миграция 0005 добавляет колонку.
DELETE /api/projects/{id} удаляет проект через service под существующей авторизацией.
ProjectGraph поддерживает редактирование связей, фильтр критических задач и подсветку последствий.
ExecutiveReportModal формирует Markdown и печатную версию средствами браузера.
Календарь позволяет задавать отпуск диапазоном дат, сохраняя его как исключения по дням.
В analyze добавлены as_of/overdue и серверное отклонение baseline_delta_minutes.
Нулевая длительность поддерживается движком, CSV и миграцией 0006; для завершённой
вехи допустимы одинаковые фактические начало и окончание.
POST /api/projects/{id}/level проверяет версию и рассчитывает предложение без записи.
Серверная эвристика меняет not_before незапущенных задач, пересчитывая суммарную
загрузку после каждого шага; зависимости и факты сохраняются. Лимит — 32 переноса,
глобальный оптимум не гарантируется. Ответ содержит число оставшихся перегрузок.
Baseline фиксируется только после расчёта актуального черновика. Изменение черновика
во время запроса отменяет применение устаревшего результата baseline/выравнивания.
Локальная копия хранит ID проекта и версию: совпадающая версия восстанавливается
по выбору пользователя, устаревшая доступна для JSON-экспорта без автоматической замены.
GET /api/projects/{id}/history возвращает последние 20 сохранённых версий.

## Безопасность и эксплуатация

Cookie HttpOnly + SameSite=Strict + Secure на HTTPS. Проверка Origin и специального заголовка для изменения данных.
Ограничение попыток входа действует внутри одного процесса; в Compose используется один worker.
В Compose Caddy перезаписывает X-Critix-Client-IP адресом соединения; API доверяет
заголовку только при TRUST_PROXY_HEADERS=true. Режим допустим только за собственным
прокси с закрытым портом API; при локальном запуске он выключен.
PostgreSQL и FastAPI не публикуют порты наружу. Caddy публикует только HTTP/HTTPS.
Сессии истекают через 8 часов. Logout отзывает токен в единственном worker; перезапуск
worker и смена SESSION_SECRET отзывают все сессии. Несколько worker не поддерживаются.
Лимиты нагрузки и резервное копирование VPS требуют проверки перед публичным запуском.

## Ограничение одновременных расчётов

Два расчётных запроса одновременно; ожидание свободного места до 3 секунд, затем явная 503.
Синхронные обработчики работают в пуле потоков FastAPI, AI не блокирует основной цикл.
Frontend имеет тайм-аут 60 секунд без автоматического повтора записей. PostgreSQL имеет
тайм-ауты подключения, блокировки и запроса. Минуты календаря хранятся массивом UTC-секунд;
datetime создаются при обращении. Новые сервисы или очереди не добавлены.
