# Critix

Инструмент руководителя проекта: изменение задачи → пересчёт последствий → решение.

## Статус

Первая реализация: календарный движок, API, PostgreSQL-модели и миграция, интерфейс,
демопроект и конфигурация VPS. Это ещё не подтверждённый публичный релиз.

- Актуализация 27.09.2026: HEAD `a8e2fff` плюс локальные изменения.
- Frontend: 12 тестов; backend с PostgreSQL: 35 тестов без пропусков.
- Проверены миграция 0006, конкурентные сохранения, восстановление черновика
  и baseline в браузере. 10 одновременных чтений и симуляций демопроекта дали HTTP 200.
- В интерфейсе используется оформление «Актион»; техническое имя проекта — Critix.
- Ошибки AI проверены без внешнего провайдера; VPS и качество реальных ответов LLM не проверялись.
- Текущее состояние и незавершённые функции: [обзор](docs/current-state.md).

## Стек

React / TypeScript / Vite / Mantine / React Flow; Python 3.12 / FastAPI / Pydantic /
SQLAlchemy 2.0 / Alembic; PostgreSQL 17; Docker Compose / Caddy.

## Возможности

Последние дополнения: AI-чат по сохранённому проекту, отчёт руководителя с экспортом
Markdown и печатью, интерактивный граф с созданием связей, роли сотрудников,
удаление проектов, отпуск диапазоном дат и обновлённая панель «Требует внимания».
Также добавлены экран команды с поиском, JSON-импорт/экспорт полного проекта,
выбор предшественника при создании задачи, уведомления, ErrorBoundary и локальная копия черновика.
Вехи поддерживаются во всех слоях; выравнивание ресурсов рассчитывается backend
и возвращает проверяемый черновик с числом оставшихся перегрузок.
Требуется миграция 0006 (`alembic upgrade head` в настроенном окружении backend).
Текущие ограничения новых функций описаны в [обзоре проекта](docs/competitive-analysis.md#актуализация-после-новых-функций).

- Проекты, задачи, исполнители без отдельных аккаунтов.
- Рабочие смены, перерывы, исключения и отпуска; пересечение двух календарей.
- IANA-пояс проекта, точность до минуты, переходы DST.
- FS, SS, FF, SF; задержки любого знака в рабочих или календарных часах.
- Прогноз завершения, резервы, критические задачи и связи, каскад изменений.
- Выявление перегрузки по процентам занятости и предложение переносов по явному запросу.
- Черновик → what-if → применение с защитой от устаревшей версии.
- AI объясняет сохранённые результаты; отключение AI не останавливает расчёты.

Подробные правила и эксплуатационные границы: [docs/architecture.md](docs/architecture.md).

## VPS

Нужен Linux VPS с Docker Engine и Compose plugin. Домен должен указывать на VPS;
входящие TCP 80/443 должны быть доступны. Порты БД и API наружу не публикуются.

1. Разместить репозиторий на VPS.
2. Скопировать `.env.example` в `.env`.
3. Заполнить `POSTGRES_PASSWORD` (URL-safe), `ADMIN_PASSWORD` (не меньше 12 символов),
   `SESSION_SECRET` (случайный, не меньше 32 символов), `SITE_ADDRESS` и `APP_ORIGIN`.
4. `SITE_ADDRESS` — домен без протокола, `APP_ORIGIN` — точный HTTPS origin без завершающего `/`.
5. Выполнить:

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 api web
```

Caddy получает TLS-сертификат автоматически. API выполняет миграции до запуска.
Открыть HTTPS-адрес, войти с `ADMIN_PASSWORD`, создать демопроект.
Для проверки здоровья: `GET /api/health`.

Не использовать `docker compose down -v` на сервере с нужными данными: это удалит том БД.
Резервная копия (Linux):

```sh
docker compose exec -T db pg_dump -U critix -d critix -Fc > critix-backup.dump
```

Хранить копию вне VPS и проверить восстановление на отдельной базе до сдачи.

## Локальная разработка

Backend:

```sh
python -m venv .venv
# Активировать окружение способом своей ОС
pip install -r backend/requirements.lock
pip install -e 'backend[test]'
```

Указать переменные `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET`,
`APP_ORIGIN=http://localhost:5173`, `COOKIE_SECURE=false` только для локального HTTP.
Для PostgreSQL нужен URL вида `postgresql+psycopg://user:password@localhost:5432/critix`.

```sh
cd backend
alembic upgrade head
uvicorn app.main:app --reload
```

Frontend, во втором терминале:

```sh
cd frontend
npm ci
npm run dev
```

Открывать именно origin, указанный в `APP_ORIGIN`. Vite проксирует `/api` к backend.

## Проверки

Изолированная проверка PostgreSQL, миграций и полного сценария API (рабочие тома не используются):

```sh
docker compose -p critix-regression -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from test
docker compose -p critix-regression -f compose.test.yaml down
```

Тестовая БД находится в памяти контейнера. Проверяется обновление старого проекта с отсутствующими
навыками, сохранность существующих навыков, вход, создание демопроекта, предпросмотр без записи,
применение изменений, повторное открытие и конфликт версий. Внешний LLM в этих тестах не вызывается.

Регрессионные тесты формы задач (Node.js 22.18+):

```sh
cd frontend
npm test
```

После изменения исходников используйте `docker compose up -d --build`: `docker compose start`
запускает старые контейнеры без пересборки. Миграция `0004` исправляет пустые списки навыков
существующих проектов автоматически при старте API.

Из корня с активным Python-окружением:

```sh
pytest backend/tests -q
```

Интеграционный тест включается переменной `TEST_DATABASE_URL`, указывающей на **отдельную
тестовую PostgreSQL** с выполненными миграциями. Он создаёт и удаляет только свой проект.
Без неё тест явно пропускается; SQLite не подменяет PostgreSQL.

```sh
cd frontend
npm run build
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/login` | Вход, `{password}` |
| POST | `/api/logout` | Выход |
| GET | `/api/projects` | Список проектов |
| POST | `/api/projects` | Создать проект из ProjectInput |
| POST | `/api/demo` | Создать отдельный демонстрационный проект |
| GET | `/api/projects/{id}` | Проект, версия и анализ |
| PUT | `/api/projects/{id}` | Применить `{version, project}` атомарно |
| POST | `/api/projects/{id}/simulate` | Рассчитать `{version, project}` без записи |
| POST | `/api/projects/{id}/level` | Предложить выравнивание `{version, project, assignee_id?}` без записи |
| POST | `/api/projects/{id}/ai` | Объяснить сохранённый анализ |
| POST | `/api/projects/{id}/chat` | Консультация, `{messages: [{role, content}], project?}` |
| DELETE | `/api/projects/{id}` | Удалить проект |

Изменяющие запросы требуют `X-Critix-Request: 1`; проектные запросы — cookie сессии.
Ошибки: 401 — вход, 403 — источник запроса, 404 — проект, 409 — устаревшая версия,
422 — поля/граф/календарь, 429 — попытки входа, 503 — настройки/AI.

4. «Показать последствия»: увидеть сдвинувшиеся задачи и новый прогноз.
5. Отменить сценарий — убедиться, что исходный план сохранён. Повторить и применить.
6. Открыть риски и запросить AI-объяснение (при настроенном провайдере).

## AI disclosure

Продукт использует OpenAI-совместимый Chat Completions API, параметры `LLM_BASE_URL`,
`LLM_API_KEY`, `LLM_MODEL`. Конкретную модель нужно выбрать и указать в презентации.
AI получает названия и рассчитанные результаты, формирует пояснения и гипотезы действий.
Граф, даты, резервы, критичность, перегрузки и дедлайн рассчитываются Python-движком.
При отсутствии ключа/модели, пустом ответе или ошибке LLM возвращается available=false
с объяснением недоступности. Шаблонные советы вместо ответа LLM не генерируются.
