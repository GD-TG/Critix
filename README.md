# Critix

Система для руководителя небольшого проекта: расчёт сроков и критического пути, проверка загрузки исполнителей и моделирование изменений до сохранения рабочего плана.

## Что реализовано

- Граф зависимостей FS, SS, FF, SF с положительными и отрицательными лагами. Циклы отклоняются.
- CPM: ранние и поздние даты, полный резерв времени, критические задачи и связи. Целевой дедлайн отделён от расчётного финиша.
- Объяснение срока в карточке задачи: определяющие зависимости и лаги, «не раньше», календарный перенос или фактические даты. Причины формирует движок; изменённый черновик требует пересчёта.
- Календари проекта и исполнителей, интервалы рабочего дня, исключения и отпуска, часовой пояс проекта. Праздники задаются вручную.
- Загрузка исполнителей в процентах, выявление перегрузок и несоответствий указанных навыков. Отдельное предложение по выравниванию ресурсов без гарантии оптимального расписания.
- Черновик, предпросмотр последствий и отдельное сохранение. What-if увеличивает длительность выбранной задачи; другие изменения проверяются через общий черновик.
- Базовый план, рассчитанный по актуальному черновику, сравнение дат и история последних 20 сохранений.
- Защита от перезаписи устаревшей версии: HTTP 409, сравнение содержимого и явный выбор версии. Запоздалые ответы не подменяют актуальные данные интерфейса.
- Таймлайн, таблица задач, граф React Flow, команда, риски, JSON-импорт/экспорт проекта, CSV-импорт/экспорт задач, Markdown-отчёт и печать средствами браузера.
- Отдельные AI-аудит и консультационный чат. Даты, граф, резервы и риски считает Python. При недоступности LLM аудит показывает сводку движка с указанием источника; чат сообщает о недоступности.
- Устаревший прогноз помечается явно. Расписание автоматически не переносится: руководитель уточняет длительности и фактические даты.

## Стек и устройство

React 19 · TypeScript · Vite · Mantine · React Flow · React Context

Python 3.12 · FastAPI · Pydantic 2 · SQLAlchemy 2 · Alembic · PostgreSQL 17 в Compose

Docker Compose · Caddy · Uvicorn (один worker)

```text
React → FastAPI REST API → Service Layer → Analysis Engine
                              ↕
                         SQLAlchemy → PostgreSQL

Результат Analysis Engine → AI-модуль backend → LLM API
```

Modular monolith: AI — модуль того же backend, отдельный сервис разворачивать не нужно. Redis, очередей и Kubernetes нет.

## Запуск

Подробные команды, настройка `.env`, миграции и устранение ошибок: **[инструкция запуска](docs/operations.md)**.

### Docker на локальном компьютере

Нужен запущенный Docker Desktop. Из корня проекта скопируйте шаблон, если собственного `.env` ещё нет:

```powershell
Copy-Item .env.example .env
notepad .env
```

Задайте собственные `POSTGRES_PASSWORD`, `ADMIN_PASSWORD`, `SESSION_SECRET`. Для локального HTTP укажите:

```dotenv
SITE_ADDRESS=http://localhost
APP_ORIGIN=http://localhost
COOKIE_SECURE=false
```

Затем:

```powershell
docker compose up -d --build
docker compose ps
```

Открывайте **http://localhost**. Compose сам запускает миграции. В нём явно включён production-режим проверки настроек; адрес `127.0.0.1` не становится разрешённым автоматически.

### Локальная разработка

Нужны PostgreSQL, Python 3.12+ и Node.js 22+. Backend запускается на порту 8000, Vite — на 5173. Открывайте **http://localhost:5173**; Vite проксирует `/api` в backend.

Установка зависимостей и точные команды для `.venv` приведены в [инструкции](docs/operations.md#локальная-разработка-в-windows). Обычный запуск Uvicorn не читает корневой `.env` автоматически: используйте показанный там `--env-file`.

## Проверки

```powershell
npm --prefix frontend ci
npm --prefix frontend test
npm --prefix frontend run build

docker compose -p critix-tests -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from test
docker compose -p critix-tests -f compose.test.yaml down
```

Тестовый Compose использует отдельную временную PostgreSQL без томов рабочего приложения и опубликованных портов. Не направляйте интеграционные тесты на рабочую базу.

Последняя проверка 29.09.2026: **50 backend-тестов пройдены**, включая объяснения дат; сборка frontend успешна. Ранее пройдены 19 frontend-тестов и браузером проверены вход, демо, What-if, сохранение, baseline и сводка без LLM. Новый блок причин ещё не проверен браузером. Есть предупреждение Vite о размере JS-бандла. Это не нагрузочный тест и не подтверждение готовности VPS или внешнего AI-провайдера.

## Ограничения

- Одна общая учётная запись руководителя. Исполнители — данные проекта, не пользователи системы. Ролей и персонального авторства действий нет.
- До 200 задач, 2000 зависимостей и 100 исполнителей; заявленный период проекта — не более года. Два одновременных расчётных запроса, затем ожидание до 3 секунд и HTTP 503 при занятости.
- Одновременная работа десяти пользователей пока не проверена нагрузочным тестом. Несколько API-worker не поддерживаются текущей схемой сессий и лимитов.
- Полный резерв рассчитывается; отдельный свободный резерв — нет. Длительность не равна трудозатратам: назначение на 50% не удваивает срок.
- Нет Монте-Карло, вероятности срыва дедлайна, бюджетной модели и доказанно оптимального выравнивания.
- LLM получает данные проекта. Качество её рекомендаций не гарантируется; проверка влияния изменений выполняется симуляцией.
- VPS ещё не проверен. Текущий Caddyfile использует `tls internal`: публично доверенный HTTPS требует отдельной настройки перед публикацией.
